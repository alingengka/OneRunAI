# ซับลาวหาย: หา root cause จริง + ขยาย guard ให้ครอบคลุม (2026-09-07)

## ช่องว่างของ guard เดิม
guard เดิมทดสอบเฉพาะ "ประโยคสังเคราะห์ จังหวะเท่ากันทุกคำ 0.4s" ผ่าน `createBurnRenderer`
โดยตรง จึงไม่มีทางเจอบั๊กที่เกิดจาก **เวลาคำจริง** ซึ่งทำให้กลุ่มซับ "ซ้อนเวลากันได้"

## Root cause ที่เจอจริง
`findWindow()` ใน `src/lib/media/burn-render.ts` (binary search ที่เพิ่มตอนงานปรับความลื่น)
สมมติว่า "ช่วงเวลาไม่ซ้อนกัน" แต่ `groupWords()` สร้างกลุ่มจากเวลาคำจริง ซึ่งซ้อนกันได้
เมื่อคำมาจาก ASR chunk ที่ overlap 0.38s (`addChunkOverlap`) หรือหลัง `mergeAlignedChunks`

ผลคือ binary search คืน `null` ทั้งที่มีกลุ่มครอบเวลานั้นอยู่ → **ซับหายทั้งกลุ่ม**
(กระทบทั้ง caption, Ken Burns motion และ viral text เพราะใช้ `findWindow` ร่วมกัน)

วัดจริงก่อนแก้: สุ่มไทม์ไลน์ที่มีกลุ่มซ้อนกัน 777,058 จุดเวลา → ซับหาย **883 จุด**
หลังแก้: **0 จุด** จาก 154,128 จุด

### การแก้
`findWindow` หา index สุดท้ายที่ `start <= time` แล้วไล่ย้อนหลังเท่าความยาวช่วงที่มากที่สุด
(cache ต่อลิสต์ด้วย WeakMap จึงยังเป็น O(log n) + คงที่ ไม่กระทบความลื่น)
เมื่อมีกลุ่มซ้อนกัน กลุ่มที่เริ่มทีหลังชนะ ซึ่งตรงกับพฤติกรรมที่ควรเห็นบนจอ

## guard ที่ขยายแล้ว (`bun run guard:lao`)
- (ก) ความแม่นยำถอดเสียง — CER เทียบ baseline (เหมือนเดิม)
- (ข) layout/burn 21 ฟอนต์ × 4 กรณี = 84 (เหมือนเดิม)
- (ค) **ใหม่: integration ผ่าน UI จริง** — Playwright เปิดแอป → อัปโหลด
  `tests/fixtures/lao-sample.wav` → เลือกภาษา ລາວ → กด "สร้างซับด้วย AI" จริง
  (ผ่าน `runTranscribe` เต็ม pipeline ไม่ mock) → อ่าน state จริง (`window.__shortcutState`)
  → เรนเดอร์ด้วย `createBurnRenderer` ไล่ทุกเฟรม 30fps ตลอดคลิป เทียบจำนวนคำที่ถอดได้
  กับคำที่ถูกวาดจริง + ตรวจว่าไม่มี "กลุ่มที่ไม่ขึ้นเลย" ทดสอบ 84 กรณี (ฟอนต์ × B/I)
- (ง) **ใหม่: property test กลุ่มเวลาซ้อนกัน** — สุ่มไทม์ไลน์ที่มีการซ้อน แล้วเทียบ
  `findWindow` กับการค้นแบบเชิงเส้น ต้องไม่มีจุดไหนที่ซับหาย
