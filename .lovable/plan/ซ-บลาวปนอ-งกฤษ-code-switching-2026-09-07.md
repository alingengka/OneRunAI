# ซับลาวที่มีคำอังกฤษแทรก (code-switching) — สาเหตุจริง (2026-09-07)

ประโยคอ้างอิงจากผู้ใช้:
> "ໄດ້ຕື່ນມາ Appreciate ສິ່ງທີ່ເຮົາມີ ແບບມັນຄື the best thing ແລ້ວ"

## วิธีทดสอบ
สร้างเสียง TTS 2 ประโยคที่มีอังกฤษแทรกกลางลาว แล้วยิงเข้าทั้ง 3 เครื่องถอดเสียงจริง
(Scribe / gpt-4o-transcribe / Gemini) และผ่าน `transcribeAudioServer` ทั้งชุด

## ผลตรวจ
- **ไม่ใช่ปัญหาการถอดเสียง**: ทั้ง 3 engine ถอดคำอังกฤษออกมาได้ครบทุกตัว
- **ไม่ใช่ `cleanup()` ในเคสทั่วไป**: ตัวกรองดูเฉพาะอักษรไทยปน อักษรละตินผ่านอยู่แล้ว
  (แต่ยังพังในเคสที่ chunk นั้นเป็นอังกฤษล้วน → `!lao` ทำให้ทิ้งทั้ง chunk)
- **สาเหตุจริงคือการให้คะแนนเลือกผู้ชนะ (ensemble scoring)**:
  `scoreCandidate` ให้คะแนน "ความบริสุทธิ์ของอักษรลาว" 28% โดยนับอักษรละตินเป็น "ไม่บริสุทธิ์"
  ผลจริงที่วัดได้ ระบบเลือก `...ຈະມາເອດິດວິດີໂອໃຫ້ມັນ viral` (สะกด edit video เป็นอักษรลาว)
  ชนะ `...ຈະມາ edit video ໃຫ້ມັນ viral` ที่ถูกต้อง
- ประกอบกับ prompt เดิมสั่ง "Use only Lao characters (U+0E80–U+0EFF)" ซึ่งบังคับให้โมเดล
  ทับศัพท์คำอังกฤษเป็นอักษรลาว

## การแก้ (`src/lib/transcribe.server.ts`)
1. prompt ของ gpt-4o และ Gemini: สั่งชัดว่าคำอังกฤษที่พูดจริงต้องเขียนด้วยอักษรละติน
   ห้ามทับศัพท์เป็นอักษรลาว และห้ามตัดทิ้ง (โหมด strict ผ่อนข้อ "Lao characters only")
2. `scoreCandidate`: ตัดอักษรละติน/ตัวเลข/เครื่องหมายออกจากการวัด purity (นับเฉพาะลาว vs สคริปต์อื่น)
   และเพิ่มคะแนน `codeSwitch` 14% ให้ candidate ที่เก็บคำอังกฤษไว้ครบที่สุด
3. `cleanup`: ยอมรับข้อความที่เป็นอังกฤษล้วน (ไม่มีอักษรลาว) ตราบใดที่ไม่มีอักษรไทยปน

ผลหลังแก้: ประโยคทดสอบทั้งสองเลือก candidate ที่คงคำอังกฤษไว้ครบ
